# 数据库表结构

本文是 Agno AIOS 当前 PostgreSQL 表结构快照。内容来自本地代码和已安装的 Agno package（`agno 2.6.12`），不是 live database introspection。

Agno 文档推荐生产存储使用 `PostgresDb`，并在多数 AgentOS 部署中把 `PgVector` 和 `PostgresDb` 放在同一个 PostgreSQL database 上。本仓库因此约定：

- Agno-owned tables 通常通过 Agno APIs 访问。
- App-owned tables 可以逐步使用同步 SQLAlchemy models 或 SQLAlchemy Core。
- Agno runtime tables 不作为 app-owned tables 重新建模；无法通过 Agno APIs 表达的读取路径需要单独设计。
- 暂不为 app-owned tables 引入异步 SQLAlchemy。Agno 当前运行时路径仍以同步 `PostgresDb` 为主，控制面表查询还没有性能证据要求 async；只有整体迁移到 Agno `AsyncPostgresDb` 或压测证明 DB 阻塞事件循环时，才重新设计异步 DB 边界。

## Schema 和归属

| Schema | 归属 | 用途 |
| --- | --- | --- |
| default schema | FastAPI Users / auth | 用户和 OAuth account records。当前 SQLAlchemy metadata 没有设置显式 schema。 |
| `app` | Agno AIOS | CVE intelligence、audit logs、evaluation runs 和 approval requests 等控制面记录。 |
| `agno` | Agno | sessions、memories、traces、spans、schedules、scheduler runs、metrics、approvals、learnings 和 component configs 等运行时记录。 |
| `mcp` | Agno AIOS | 集成 MCP token 和 Hi-Agent execution cache records。 |
| `knowledge` | Agno / Agno AIOS | Knowledge content catalog 和 PgVector vector index。 |

## Auth tables

### `user`

归属：FastAPI Users，通过 SQLAlchemy 管理。

关键列：

- `id`：`CHAR(36)`，主键，默认 UUID。
- `email`：`VARCHAR(320)`，唯一索引 `ix_user_email`。
- `hashed_password`：`VARCHAR(1024)`。
- `is_active`、`is_superuser`、`is_verified`：boolean flags。
- `role`：`VARCHAR(32)`，Agno AIOS 扩展列，默认 `user`。

### `oauth_account`

归属：FastAPI Users，通过 SQLAlchemy 管理。

关键列：

- `id`：`CHAR(36)`，主键，默认 UUID。
- `user_id`：`CHAR(36)`，指向 `user.id`。
- `oauth_name`、`account_id`、`account_email`：OAuth provider account 标识。
- `access_token`、`refresh_token`、`expires_at`：OAuth token 状态。

## App schema

### `app.cves`

归属：Agno AIOS。当前由 `api.services.postgres_store.ensure_app_tables()` bootstrap，是后续迁移到 app-owned SQLAlchemy persistence layer 的候选。

用途：存储 CVE intelligence records。

关键列：

- `id`：`BIGSERIAL`，主键。
- `cve_id`：`TEXT`，由 `idx_cves_cve_id` 建索引。
- `description`：`TEXT`。
- `github_url`：`TEXT`，属于 unique constraint `uq_cves_cve_url`。
- `source`：`TEXT`，由 `idx_cves_source` 建索引。
- `create_time`、`created_at`、`updated_at`：时间字段。

附加索引：`idx_cves_search` 是覆盖 `cve_id` 和 `description` 的 GIN full-text index。

### `app.audit_logs`

归属：Agno AIOS。

用途：记录安全相关操作的 audit log。表定义、索引、insert 和 list 查询集中在 persistence layer，service 层只保留 actor/context 投影。

关键列：

- `id`：`BIGSERIAL`，主键。
- `actor_user_id`、`actor_email`、`actor_role`：actor identity。
- `action`：审计动作；与 `created_at` 通过 `idx_audit_logs_action_time` 建索引。
- `resource_type`、`resource_id`：目标资源。
- `status`：默认 `success`。
- `ip_address`、`user_agent`：请求上下文。
- `metadata`：`JSONB`，默认 `{}`。
- `created_at`：创建时间。

附加索引：`idx_audit_logs_actor_time` 覆盖 `(actor_user_id, created_at DESC)`。

### Legacy: `app.chat_session_archives`

归属：Agno AIOS legacy table。

用途：曾用于记录 Chat Session soft archive 状态。当前迁移目标是把 archive marker 存入 `agno.agno_sessions.metadata`，代码不再创建或读写该 table。

关键列：

- `session_id`：`TEXT`，主键；引用 Agno chat session id，但没有声明 foreign key。
- `user_id`：archive owner。
- `archived_at`、`reason`、`metadata`：archive 状态。

### `app.os_eval_runs`

归属：Agno AIOS。

用途：存储 AIOS 控制面 evaluation records。

关键列：`id`、`name`、`target`、`status`、`score`、`created_at`、`updated_at`、`metadata`。

### `app.os_approvals`

归属：Agno AIOS。

用途：存储 AIOS 控制面 approval requests。

关键列：`id`、`title`、`requester`、`action`、`status`、`created_at`、`updated_at`、`metadata`。

## MCP schema

### `mcp.mcp_tokens`

归属：Agno AIOS。

用途：存储 MCP endpoint token。

关键列：

- `id`：`BIGINT GENERATED BY DEFAULT AS IDENTITY`，主键。
- `name`：token label。
- `token`：唯一 token value。
- `created_at`：epoch timestamp。
- `expires_at`：epoch timestamp；`0` 表示不过期。

### `mcp.hiagent_exec_cache`

归属：Agno AIOS。

用途：存储 Hi-Agent execution cache。

关键列：

- `exec_id`：`TEXT`，主键。
- `tool_name`：remote tool name。
- `status`：execution status。
- `result`、`error`：执行结果或错误。
- `created_at`：用于 cache ordering。
- `updated_at`：更新时间。

附加索引：`idx_hiagent_exec_created_at` 覆盖 `created_at`。

## Agno schema

以下 tables 归 Agno 所有。优先使用 Agno `PostgresDb`、`ScheduleManager`、AgentOS 或 tracing APIs，不直接 SQL。

### `agno.agno_schema_versions`

用途：记录 Agno-managed schema version。

关键列：`table_name`、`version`、`created_at`、`updated_at`。

### `agno.agno_sessions`

用途：存储 Agent、team 和 workflow sessions。

关键列：

- `session_id`：主键。
- `session_type`：Agent、team 或 workflow session type。
- `agent_id`、`team_id`、`workflow_id`、`user_id`：runtime identity。
- `session_data`、`agent_data`、`team_data`、`workflow_data`：runtime payload。
- `metadata`：扩展 metadata，可承载 AIOS soft-archive marker。
- `runs`、`summary`：run history 和 session summary。
- `created_at`、`updated_at`：epoch timestamps。

索引：`idx_agno_sessions_created_at`、`idx_agno_sessions_session_type`。

### `agno.agno_memories`

用途：存储 Agno user memories。

关键列：`memory_id`、`memory`、`feedback`、`input`、`agent_id`、`team_id`、`user_id`、`topics`、`created_at`、`updated_at`。

索引：`idx_agno_memories_created_at`、`idx_agno_memories_updated_at`、`idx_agno_memories_user_id`。

### `agno.agno_traces`

用途：存储 Agno trace records。

关键列：`trace_id`、`name`、`status`、`start_time`、`end_time`、`duration_ms`、`run_id`、`session_id`、`user_id`、`agent_id`、`team_id`、`workflow_id`、`created_at`。

索引：`idx_agno_traces_agent_id`、`idx_agno_traces_created_at`、`idx_agno_traces_run_id`、`idx_agno_traces_session_id`、`idx_agno_traces_start_time`、`idx_agno_traces_status`、`idx_agno_traces_team_id`、`idx_agno_traces_user_id`、`idx_agno_traces_workflow_id`。

### `agno.agno_spans`

用途：存储 Agno span records。

关键列：`span_id`、`trace_id`、`parent_span_id`、`name`、`span_kind`、`status_code`、`status_message`、`start_time`、`end_time`、`duration_ms`、`attributes`、`created_at`。

索引：`idx_agno_spans_created_at`、`idx_agno_spans_parent_span_id`、`idx_agno_spans_start_time`、`idx_agno_spans_trace_id`。

### `agno.agno_schedules`

用途：存储 Agno Scheduler schedules。

关键列：`id`、`name`、`description`、`method`、`endpoint`、`payload`、`cron_expr`、`timezone`、`timeout_seconds`、`max_retries`、`retry_delay_seconds`、`enabled`、`next_run_at`、`locked_by`、`locked_at`、`created_at`、`updated_at`。

索引：`idx_agno_schedules_created_at`、`idx_agno_schedules_enabled_next_run_at`、`idx_agno_schedules_name`、`idx_agno_schedules_next_run_at`。

### `agno.agno_schedule_runs`

用途：存储 Agno Scheduler run history。

关键列：`id`、`schedule_id`、`attempt`、`triggered_at`、`completed_at`、`status`、`status_code`、`run_id`、`session_id`、`error`、`input`、`output`、`requirements`、`created_at`。

索引：`idx_agno_schedule_runs_created_at`、`idx_agno_schedule_runs_schedule_id`、`idx_agno_schedule_runs_status`。

### 可选 Agno AgentOS tables

本地 Agno `PostgresDb` 还暴露 `agno_metrics`、`agno_approvals`、`agno_learnings`、`agno_components`、`agno_component_configs` 和 `agno_component_links` 等 tables。如果 AgentOS 或未来 Agno integrations 创建这些 tables，应视为 Agno-owned。没有单独 ADR 时，不要把它们建模为 app-owned tables。

## Knowledge schema

### `knowledge.agno_knowledge`

归属：Agno `PostgresDb` contents catalog for `Knowledge`。

用途：存储 Knowledge content catalog。

关键列：`id`、`name`、`description`、`metadata`、`type`、`size`、`linked_to`、`access_count`、`status`、`status_message`、`created_at`、`updated_at`、`external_id`。

### `knowledge.security_knowledge_vectors`

归属：Agno `PgVector` vector index。默认表名来自 `AGNO_KNOWLEDGE_PGVECTOR_TABLE`。

用途：存储 Knowledge Document chunks 和 embedding vectors。

关键列：`id`、`name`、`meta_data`、`filters`、`content`、`embedding`、`usage`、`created_at`、`updated_at`、`content_hash`、`content_id`。

`id`、`name`、`content_hash` 和 `content_id` 的索引由 Agno/PgVector 生成。Vector index 细节由本地 `PgVector` 配置控制。

## Agno-owned 替代候选

创建 SQLAlchemy models 之前，应先审查以下 app-owned records，因为 Agno 已经暴露了相近的 owned capabilities。

| 当前 table 或 concern | 当前归属 | Agno-owned capability | 建议 |
| --- | --- | --- | --- |
| `app.chat_session_archives` | Agno AIOS legacy | `agno.agno_sessions.metadata`、`PostgresDb.get_session()`、`PostgresDb.get_sessions()`、AgentOS Session Update API | 已作为第一批收敛目标：soft-archive marker 存在 session `metadata`，代码移除单独 archive table 的创建和读写。保留 AIOS API facade，因为 Agno 文档中的 session list filter 覆盖 type、component、user 和 name，不覆盖 metadata。 |
| Chat session hard delete | Agno | `PostgresDb.delete_session()` 和 AgentOS Delete Session API | 不用于 AIOS archive 语义，除非产品明确从 soft archive 改为永久删除。 |
| `app.os_eval_runs` | Agno AIOS | `PostgresDb.create_eval_run()`、`get_eval_run()`、`get_eval_runs()` 和 AgentOS eval APIs | 当 record 表示真实 agent/team/workflow evaluation 时优先使用 Agno eval runs。只有 AIOS-specific drafts 或 planning records 不属于 Agno eval results 时，才保留 app-owned table。 |
| `app.os_approvals` | Agno AIOS | `PostgresDb.create_approval()`、`get_approvals()`、`update_approval()` 和 AgentOS approval APIs | paused runs、approval lifecycle 和 audit approvals 优先使用 Agno approvals。只有非 Agno operator workflow requests 才保留 app-owned table。 |
| Scheduler records | Agno | `ScheduleManager` 和 Agno `agno_schedules` / `agno_schedule_runs` | 已与 Agno-owned storage 对齐；避免重新引入 `app.os_schedules`。 |
| Metrics | Agno | `PostgresDb.calculate_metrics()` 和 `get_metrics()` | AgentOS runtime metrics 优先使用 Agno metrics。AIOS-specific dashboard projections 不写入 Agno tables。 |
| `knowledge.agno_knowledge` 和 vector rows | Agno / PgVector | Agno `Knowledge`、`PostgresDb` contents DB、`PgVector` | 保持 Agno-owned。AIOS 通过 metadata 和 service-level checks 执行 ownership 与 presentation，不重新定义这些 tables。 |

仍然明确属于 app-owned 的 tables：`app.audit_logs`、`app.cves`、`mcp.mcp_tokens` 和 `mcp.hiagent_exec_cache`。它们表示 AIOS security control-plane behavior 或 integrated MCP access，而不是 Agno runtime state。

## 迁移建议

新的或被重构的 app-owned tables 应在 `app` 和 `mcp` schemas 中使用同步 SQLAlchemy。Agno Runtime Data 和 Knowledge vector tables 应继续放在 Agno `PostgresDb`、`ScheduleManager`、`Knowledge` 和 `PgVector` APIs 后面。异步 SQLAlchemy 不是默认迁移目标；需要单独 ADR 说明性能证据、Agno runtime async 边界和调用方改造计划。
