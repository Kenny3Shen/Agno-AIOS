深化后

小 Run interface

deep Agent Runtime module

model adapter MCP Service adapter Knowledge Base adapter fallback policy

route 保留 SSE formatting；Run policy 获得 locality。

问题

当前 interface 由大量原始参数组成，callers 必须理解执行顺序和 runtime policy，这些知识应该集中在一个 module 中。

方案

围绕完整 Run orchestration 深化 Agent Runtime；把 adapters 放在 seam 后面，并降低 `llm_service.py` 的 pass-through 压力。

收益

  • locality：Run policy 集中在一个 module
  • leverage：服务 Chat、Scheduler、Workflow callers
  • tests 命中同一个 interface

Backend Permission and Audit Log policy module

ADR-0003 规定 backend permission checks 是安全 seam；当前 tests 经常检查 route 源码字符串，而不是驱动一个 policy module。

Strong（强） mock
ADR 说明：强化 ADR-0003。它不会把安全移动到 frontend；它让 backend policy 成为 test surface。

涉及文件

api/auth/permissions.py api/services/audit_service.py api/routes/*.py api/tests/test_audit_log_permissions.py api/tests/test_chat_session_permissions.py api/tests/test_data_route_permissions.py

当前结构

深化后

backend policy interface
deep Permission + Audit Log policy module：required permission、Resource Ownership、audit action、failure shape
route adapter
test adapter

问题

source-string tests 很脆弱；它们验证 implementation 文本，而不是 backend Permission 与 Audit Log 的 interface。

方案

把 backend policy 深化成一个 module，让 routes 通过稳定 seam 声明 policy，tests 使用同一个 seam。

收益

  • locality：policy changes 本地化
  • leverage：所有 routes 共用 module
  • tests 不再读取源码字符串
